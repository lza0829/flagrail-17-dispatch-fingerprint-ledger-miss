# 灰度轨

中文名：**灰度轨** · 前缀 `flagrail` · 端口 **6800 / 11800**

## 骨架

**开关版本入轨 → 分桶灰度下发 → 回读确认 → 失效/回滚互证**

皮：功能开关 / 配置灰度控制台。去皮是 **版本入轨 + 分桶下发 + 回读确认 + 命运互证**，不是配置 CRUD、不是 RBAC、不是发版审批闸。

领域：**基础设施** · 子方向：**中间件**

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6800
# 开关轨 → 入轨样例 → 分桶规 → 下发 → 回读样例 → 轨贯验 → 回滚样例
```

## 下发回读计划同票（已落地）

禁止「有票无计划」假成功。一次 `POST /api/下发` 在同一个 `BEGIN IMMEDIATE`
事务内同时落：**下发票（已下发）+ 回读计划行 + 开关版本灰度态 + 命运账**，
四者同成败、同事务可见；同「版本+桶」第二次下发交错时失败闭（事务内槽位检查
+ 部分唯一索引 `唯一在途有效下发` 双保险）。

计划表：`回读计划行`（并以可更新视图 `回读计划` 暴露同名关系，直接对视图
INSERT 也会落到计划表）。

计划核证路由（GET/POST 均可，别名 `/api/核证`、`/api/计划/核证`、`/api/certify`、
`/api/verify`、`/api/回读计划核证`、`/api/回读计划/核证`、
`/api/下发回读计划同票/核证`、`GET /api/下发票/{票号}/核证`）
返回契约 exactly：

```json
{ "票号": "...", "计划有无": true, "缺计划标记": false, "可否晋升": false, "valid": true }
```

`缺计划标记` 为有效标记 = 存储标记 `缺计划` OR 派生的「暗缺计划」
（票已下发但库里零计划行，用于抓历史裸孤儿）。`valid` 要求已下发、有计划、
无缺计划标记；`可否晋升` 还要求必需边缘回读齐套且无偏差。缺计划时
`POST /api/回读` 与 `POST /api/全量晋升` 一律拒绝，贯验点名
`有票无计划假已下发:{票号}`。

计划写失败允许两种口径，可经 body `计划失败口径`、query、请求头
`x-plan-failure-mode`、环境变量 `FLAGRAIL_PLAN_FAILURE_MODE` 或站规
`计划失败口径` 选择（默认 `回退`）：

- **口径一·甲（回退 rollback）**：`SAVEPOINT` 回滚计划步并整体回退，票不得停留
  已下发，落到独立的 `下发失败` 票，计划行不存在；用同票号重发可走通。
- **口径二·乙（悬挂 dangling）**：票保持已下发但置 `缺计划=1`，补建计划前
  确认回读与全量晋升全拒；`POST /api/补计划` 补行并清除标记后走通。

两口径在「失败瞬间 GET 票是否已下发、晋升是否放行」上可区分。

失败注入自动化（stdlib-only，真实 uvicorn 并发断言，含「断言假已下发」）：

```bash
# 先起后端（默认 http://127.0.0.1:11800），然后：
bash scripts/失败注入.sh
# 或
python3 scripts/失败注入_计划同票.py --base http://127.0.0.1:11800
# 末步注入也可随 /api/下发 body {"计划写失败": true, "计划失败口径": "悬挂"} 触发；
# 或先 POST /api/故障注入 {"口径":"回退|悬挂"}（默认剩余次数=1，一次性，
# 显式 "剩余次数":-1 为持续武装，POST /api/故障注入/复位 解除），再发干净请求。
```

脚本覆盖甲/乙两口径、`/api/故障注入` 开关一次性与口径优先级、裸孤儿核证与治愈、
8 票号交错（恰 1 成功）、6 同票号并发（一行一票、计划不重复），同卷重复运行稳定，
当前 `55 通过 / 0 失败`。补建入口另有票号路径别名
`POST /api/下发票/{票号}/补计划`。下发票页与回读台均可视化计划有无、缺计划标记
（暗缺计划脉冲红）与核证五字段，轨台在出现缺计划票时亮警示条。
